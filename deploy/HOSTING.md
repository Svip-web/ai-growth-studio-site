# Розміщення на звичайному хостингу

Сайт залишається статичним; тільки `api/lead.php` потребує PHP. Cloudflare, Apps Script і база даних не потрібні.

## Вимоги

- PHP 8.1 або новіший, розширення cURL і sessions.
- HTTPS на домені та вихідні HTTPS-запити до `api.telegram.org:443`.
- Робоче сховище PHP-сесій і папка `private/`, доступна PHP для запису.
- Перевірка TLS-сертифікатів має залишатися увімкненою.

## Структура папок

```text
hosting-root/
├── private/
│   └── ai-growth-telegram.php  ← справжній токен, НЕ публікувати
└── public_html/
    ├── index.html
    ├── en.html
    ├── assets/
    └── api/
        ├── lead.php
        └── lead-lib.php
```

Скрипт `npm run package:hosting` збирає лише необхідні публічні файли в `../outputs/ai-growth-hosting/public_html/`. Він не читає і не копіює токен. Локальний приватний конфіг нового бота зберігається окремо в `../outputs/ai-growth-hosting/private/`.

1. Завантажте вміст `public_html/` у вебкорінь хостингу.
2. Завантажте `private/` **на рівень вище вебкореня**, не всередину нього. Рекомендовані права: приватна папка 700, конфіг 600, з доступом для користувача PHP.
3. Якщо структура хостингу відрізняється, задайте серверну змінну `STUDIO_TELEGRAM_CONFIG` з абсолютним шляхом до приватного конфіга. Не переносіть токен у JavaScript, HTML або GitHub.
4. Після отримання домену оновіть canonical/hreflang у `index.html` і генераторі `scripts/i18n.cjs`, потім перезберіть. Наразі вони посилаються на чинний GitHub Pages.
5. За reverse proxy налаштуйте коректний `HTTPS` у PHP та, за потреби, точний `allowed_origins` у конфігу. CORS `*` не вмикайте.
6. Перевірте обидві мови й обидві форми на реальному HTTPS-домені. Надішліть позначену тестову заявку та переконайтеся, що вона з’явилася в приватній групі.

Не завантажуйте `.git`, `scripts`, вихідні фото або приватний конфіг у вебкорінь. Нікому не пересилайте весь пакет із `private/`, крім довіреного адміністратора хостингу.

## Поведінка форм

- В обох мовах готовий фінальний вигляд форми, без тимчасових написів про перенесення. GitHub Pages не виконує PHP: спроба надсилання там показує помилку та посилання на Telegram, а не удаваний успіх.
- На PHP-хостингу відносний `api/lead.php` працює без зміни клієнтського коду, також у підкаталозі.
- «Заявка отправлена» з’являється тільки після підтвердження Telegram. При помилці поля зберігаються.
- Захист: CSRF і same-origin, перевірка та обмеження полів, honeypot, 5 спроб за 15 хвилин на IP (зберігається тільки HMAC), блокування повторних кліків та ідемпотентні повтори в межах PHP-сесії.
- Не підтверджена через мережу доставка не повторюється автоматично. У такому випадку слід перевірити Telegram, а не надсилати іншу заявку.
- При зміні токена через BotFather оновіть тільки приватний конфіг. Бот має залишатися учасником групи. Якщо група перетвориться на супергрупу, її chat_id потрібно оновити.

## Перевірки

`npm run build && npm test`; за наявності PHP: `php -l api/lead.php`, `php -l api/lead-lib.php`, `php scripts/test-leads.php`.

Англійська версія генерується з `index.html` та `assets/translations/en.json`. Не редагуйте `en.html` вручну; після змін перезапустіть build. Відеовідгуки залишаються мовою оригіналу, про що є примітка.
